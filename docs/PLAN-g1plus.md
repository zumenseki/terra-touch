# 創世 G1+ ロードマップ (G0.5〜G1.6)

要望「視点移動を楽に / 個体・性差 / 狩り / 動物 / 人・家をリアルに」+ 既定次工程 G1植生 を、
完全無料(APIキー/サーバ不要・GitHub Pages静的配信・全て手続き生成)で実現する計画。

18エージェントのワークフロー(コード精読5 + 技術調査6 + 設計3案 + 審査3 + 統合1)で策定。
3設計案(シム深度優先/見た目優先/バランス増分)を審査 → **バランス増分案が勝者**、敗者案から8アイデアを移植。

総工数 10〜15セッション。各マイルストーンは「3秒で分かる見える変化 + 系の深化」をペアで持ち、単体でデプロイ可能。

## 要望 → マイルストーン対応
1. 視点移動を楽に = **M1**(ズーム中心/地面パン/フォーカス/WASD/チルト/めり込み)
2. 個体・性差 = **M2**(性差三層 + 歩容 + 色)
3. 狩り = **M5**(Utility AI + 追跡 + 食料経済)
4. 動物 = **M4**(4種・群れ抽象・採食圧還流)
5. 人・家リアル化 = 人**M2**(関節+体格) / 家**M6**(3段成長+小物+材質)。CC0 GLB/SkinnedMeshは路線衝突で不採用
6. G1植生+目的行動+水やり行動変化 = **M3**(植生+水やり緑化)+**M5**(水飲み/採集/帰宅の目的行動)

## 重要な設計判断
- 骨格=バランス増分案。依存順(変形追従→インスタンス化で予算解放→植生→動物→狩り)が唯一、作り直しゼロ。
- 経済は村単位stock-flow・代表者イベント非依存(PC/スマホのcap差が成長速度に影響しない)。
- 不採用: GOAP(過剰) / GPU boids(オーバーキル) / SkinnedMesh・CC0 GLB(instancing/路線衝突) / 地上一人称(テクセル31m vs 人172m相当の重大スケール衝突)。

## 主リスク
- M2 描画リライト=退行リスク最大 → callsDelta assert + ヘッドレス回帰スイートで機械検知。
- GPU/CPU二重実装+30% → 全verifyを両経路で必須化。
- 決定論の完全一致は CPU経路を正・GPU経路は許容誤差比較(浮動小数点順序/非同期readback)。
- カメラ手触りの最終判定は実機目視(ヘッドレスは状態量整合まで)。
- heightUV動的化=挙動変更(彫削で既存村が不適地化し縮小し得る)=ゲーム的に正しい創発として受容。
